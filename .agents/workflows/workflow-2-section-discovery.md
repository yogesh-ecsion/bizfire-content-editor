# Workflow 2: AI Section Discovery & page-template.json

**Purpose:** Intelligently scan the designer HTML, identify every visual section boundary
(even in non-semantic div-soup), and generate the `page-template.json` layout recipe.
Run this ONCE per page, AFTER Workflow 1 completes.

**Prerequisite:** Read `.agents/context/BIZFIRE_CONTEXT.md` before starting.

---

## USER INPUTS (fill before running)

```
WORKSPACE_ID     = [e.g. "acme-plumbing-001"]
TEMPLATE_ID      = [e.g. "acme-plumbing-main"]
TEMPLATE_NAME    = [e.g. "Acme Plumbing Main Landing Page"]
HTML_SOURCE_PATH = [e.g. "temp/Demo-html/index.html"]
```

---

## Step 1 — Read Full HTML Source

Open and read the ENTIRE file at `[HTML_SOURCE_PATH]`.
Do not summarize or skip. Read every line.

---

## Step 2 — Identify Header & Footer Boundaries

Locate the site header and site footer in the HTML:
- Header: typically the first `<header>` tag, or the first major `<nav>` wrapper.
- Footer: typically the last `<footer>` tag, or the final wrapper with copyright text.

Record the exact opening and closing tags for both. These will be excluded from the
body component inventory and handled in Workflow 4.

---

## Step 3 — Identify All Body Sections

Working only on the HTML between the header and footer:

Scan the document top to bottom. Identify each distinct visual section by looking for:
- Semantic tags: `<section>`, `<article>`, `<aside>`
- Presentational wrappers: `<div class="...">` where the class name suggests a major block
  (e.g. `hero`, `services`, `testimonials`, `cta`, `faq`, `footer`, `banner`, `grid`)
- Visual context clues: large blocks of content with their own heading (`<h1>`, `<h2>`)

For each section found, record:
1. **Index** — Sequential number (#1, #2, ...)
2. **Component Key** — kebab-case slug you assign (e.g. `acme-hero-split`, `services-grid`)
3. **Component Name** — Human-readable (e.g. "Split Hero Section", "Services Grid")
4. **Category** — One of: Hero, CTA, Services, Testimonials, FAQ, Process, Marquee, Stats, Content
5. **Outermost Selector** — The exact tag + class of the topmost container (e.g. `<section class="hero-wrapper">`)
6. **Landmark Text** — The first visible headline or key text in that section

Output this as a markdown table:

| # | Component Key | Name | Category | Outermost Selector | Landmark Text |
|---|---|---|---|---|---|
| 1 | acme-hero-split | Split Hero | Hero | `<section class="hero-wrapper">` | "24/7 Emergency Plumbing..." |

---

## Step 4 — Generate page-template.json

After the inventory table, immediately create the file at:
`workspaces/[WORKSPACE_ID]/theme/page-templates/[TEMPLATE_ID].json`

```json
{
  "id": "[TEMPLATE_ID]",
  "name": "[TEMPLATE_NAME]",
  "description": "Full landing page template generated by AI from designer mockup.",
  "components": [
    { "type": "component-key-1" },
    { "type": "component-key-2" }
  ]
}
```

The `components` array must list component keys in the SAME ORDER as they appear in the HTML,
top to bottom. Every section from the inventory table must be represented.

---

## Completion Criteria

- [ ] All visual sections are listed in the inventory table (zero sections missed).
- [ ] `page-template.json` created with ALL component keys in correct order.
- [ ] Component keys are unique, kebab-case, and descriptive.
- [ ] Header and footer are noted but NOT included in `components` array.

**Next:** Run Workflow 3 once for each component in the inventory table.
Run Workflow 4 for the header and footer.
